# Alify UI audit and forms remediation — 7 Nov 2026

## Confirmed form UI gap and resolution

### Form / Form Template editor depended on ACF Pro

The original form builder, reusable-template picker, per-form recipient, and confirmation message were registered only through ACF. Without ACF Pro, users could see a post type but had no useful form-definition interface.

**Implemented:** Alify now provides a native field builder for both Forms and Form Templates. It supports text, email, phone, URL, long-answer, dropdown, radio, and checkbox fields; required state; per-choice values; field reordering/removal; template selection; delivery recipient; confirmation message; and a ready-to-copy shortcode. The native Forms Settings page provides site-wide notification, success-message, and Privacy Policy defaults when ACF options pages are unavailable. Existing ACF repeater metadata is read and converted into the native builder format when a definition is saved.

### Public form UX improvements

- Configured forms now show a required-fields note and place the submit action in a full-width responsive action row.
- Choice controls and status notices receive matching front-end styling.
- Validation failures now map to useful, safe messages (required fields, email/URL, invalid choice, privacy consent, rate limit, expired nonce, and other cases) without putting submitted values into the URL.
- On an intentional submit, recoverable field values are kept in same-tab `sessionStorage` for a one-time restore after a server-side validation redirect. Consent, hidden security values, and files are excluded; success/error results clear the recovery data.
- Error notices use alert semantics and receive focus/scroll into view after redirect.
- Form editing no longer tells administrators to fix definitions in ACF; the message points to the native Form Fields panel.
